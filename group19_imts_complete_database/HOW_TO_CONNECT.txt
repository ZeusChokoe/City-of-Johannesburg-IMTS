  ================================================================================
  STEP 1 — XAMPP: Start MySQL
  ================================================================================

  1. Open XAMPP Control Panel
  2. Click START next to MySQL
  3. Click START next to Apache (needed for phpMyAdmin)
  4. Confirm both show green "Running" status
  5. Open http://localhost/phpmyadmin in your browser

  LOAD PHASE 1 — Database Schema:
    phpMyAdmin → left sidebar → click the "Import" tab (top menu)
    → Choose File → select:  phase1_mysql/group19_schema.sql
    → Click Go

    You should see "group19" appear in the left sidebar with 11 tables:
    assets, asset_types, districts, inspections, maintenance_requests,
    parts_inventory, parts_usage, request_status_history, staff,
    work_order_assignments, work_orders

  LOAD PHASE 2 — Business Logic (Triggers, Procedures, Events, Functions):
    IMPORTANT: Do NOT use the SQL tab for this file.
    Use: phpMyAdmin → select "group19" database → Import tab
    → Choose File → select: phase2_mysql_logic/group19_logic.sql
    → In the "Format" section, ensure delimiter is set to ;
    → Click Go

    Verify: click on the "group19" database → Routines tab
    You should see 5 functions + 6 stored procedures listed.

    Alternative (MySQL Workbench — recommended for Phase 2):
    File → Open SQL Script → select group19_logic.sql → Execute All (lightning bolt)

  MySQL connection details:
    Host:     127.0.0.1
    Port:     3306
    User:     root
    Password: (blank — XAMPP default)
    Database: group19

  ================================================================================
  STEP 2 — MongoDB: Start Service
  ================================================================================

  CHECK IF RUNNING:
    Open a terminal and type:  mongosh
    If you get the mongosh prompt → MongoDB is running (type exit to leave)
    If you get "command not found" or connection error → see fixes below

  START MONGODB:
    Windows:   Open Command Prompt as Admin → net start MongoDB
    Windows:   OR open Services (Win+R → services.msc) → find MongoDB → Start
    macOS:     brew services start mongodb-community
    Linux:     sudo systemctl start mongod

  LOAD PHASE 3 — Collections, Indexes, Seed Data:
    Open a terminal in the group19_imts/ folder and run:
    
      mongosh --file phase3_mongodb/group19_mongodb.js

    This creates:
      - Database: group19_mongo
      - 5 collections with JSON Schema validation
      - All indexes (TTL, geospatial, compound)
      - Realistic seed documents

  VERIFY in mongosh:
      use group19_mongo
      show collections
      db.maintenance_logs.countDocuments()      // should return 6
      db.sensor_readings.countDocuments()       // should return 30

  VERIFY in MongoDB Compass (GUI):
    Open Compass → Connect to mongodb://localhost:27017
    → Select group19_mongo database → browse collections

  MongoDB connection details:
    URI:      mongodb://127.0.0.1:27017
    Database: group19_mongo
    Auth:     none (local Community Edition)

  ================================================================================
  STEP 3 Neo4j: Start Database
  ================================================================================

  1. Open Neo4j Desktop application
  2. In your project, click START on your database
    (If you have no database yet: New → Local DBMS → name it "group19" → set a password → Create → Start)
  3. Click Open → Neo4j Browser
    The browser opens at http://localhost:7474

  WRITE DOWN YOUR PASSWORD you need it for .env files.

  LOAD PHASE 4 Nodes, Relationships, Cypher Queries:
    Open phase4_neo4j/group19_neo4j.cypher in a text editor.
    Copy and paste each SECTION separately into Neo4j Browser.
    Press Ctrl+Enter (or the ▶ play button) after each section.

    SECTION ORDER do not skip, do not change order:
      Section 1: Constraints and Indexes     (CREATE CONSTRAINT... blocks)
      Section 2: Node Creation               (MERGE (d1:District...) blocks)
      Section 3: Relationship Creation       (MATCH...MERGE relationship blocks)
      Section 4: Cypher Query Library        (MATCH queries run to verify)
      Section 5: Verification                (MATCH (n) RETURN labels(n)...)

  VERIFY in Neo4j Browser:
      MATCH (n) RETURN labels(n)[0] AS label, count(n) AS count ORDER BY count DESC
      Should show: Asset(18), Technician(7), District(7), AssetType(10)...

  Neo4j connection details:
    Browser:  http://localhost:7474
    Bolt URI: bolt://127.0.0.1:7687
    User:     neo4j
    Password: (the one you set in Neo4j Desktop)

  ================================================================================
  STEP 5 Start the REST API
  ================================================================================

  1. Open a terminal in phase5_api/ and run:
      npm install

  2. Copy the environment file:
    Windows:      copy .env.example .env
    macOS/Linux:  cp .env.example .env

  3. Open .env and set:
      MYSQL_PASSWORD=          (leave blank for XAMPP default)
      NEO4J_PASSWORD=          (your Neo4j password from Step 3)
      MONGO_URI=mongodb://127.0.0.1:27017

  4. Start the API:
      node server.js

  EXPECTED STARTUP OUTPUT:
    === Group 19 City of Johannesburg IMTS API ===
    [MySQL]   Connected -> database: group19
    [MongoDB] Connected -> database: group19_mongo
    [Neo4j]   Connected -> bolt://127.0.0.1:7687
    Database status: 3/3 connected
    API running -> http://localhost:3000/api/v1

  NOTE: The API uses a PARTIAL START approach if one database is down it
  still starts and serves the other databases. Broken endpoints show a clear
  error message rather than crashing the whole server.

  ================================================================================
  TROUBLESHOOTING
  ================================================================================

  Problem: phpMyAdmin gives error 1064 on Phase 2 SQL
  Fix:     Use the IMPORT tab (not SQL tab). The file uses DELIMITER $$
          which the SQL tab does not handle. The Import tab does.
          Better: use MySQL Workbench it handles DELIMITER natively.

  Problem: Phase 2 events give "Event scheduler is off" warning
  Fix:     Run this in phpMyAdmin SQL tab:
            SET GLOBAL event_scheduler = ON;
          Then re-run the Phase 2 import.

  Problem: mongosh: command not found
  Fix:     MongoDB Shell is separate from MongoDB Server.
          Download mongosh from: https://www.mongodb.com/try/download/shell
          Or use full path: "C:\Program Files\MongoDB\Tools\100\bin\mongosh.exe"

  Problem: MongoDB validation error when running Phase 3
  Fix:     Drop the database first if it exists from a partial run:
            mongosh → use group19_mongo → db.dropDatabase()
          Then re-run the Phase 3 script.

  Problem: Neo4j "Already exists" on constraints
  Fix:     Safe to ignore IF NOT EXISTS prevents duplicates.
          Continue to the next section.

  Problem: API starts but /health/deep shows Neo4j UNREACHABLE
  Fix:     Check NEO4J_PASSWORD in phase5_api/.env matches the password
          set in Neo4j Desktop exactly (case-sensitive).

  Problem: DB Manager shows "API server not reachable"
  Fix:     The API must be running first. Open a terminal in phase5_api/
          and run: node server.js
          Keep that terminal open while using the dashboard.

  Problem: DB Manager edit saves but data does not change
  Fix:     Some columns (created_at, updated_at) are auto-managed by
          MySQL triggers. Changes to those fields are intentionally
          blocked by the trigger this is correct behaviour.

  Problem: Cannot delete from request_status_history
  Fix:     This is intentional. The audit table is immutable by design.
          See GA9 Reflection document for the reasoning.

    failure cascade analysis, shortest path routing, electrical dependency

    Node.js/Express with 3 DB connections, 12 operational endpoints,

    partial-start resilience, graceful SIGTERM shutdown.
